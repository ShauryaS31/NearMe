# P18: Editable Trip Planner and honest transit handoff

## Request and scope
Owner explicitly requested one dedicated subagent to let users type origin and destination in the existing guided trip planner, select a departure time, replace generic example Trip 1/2/3 rows with a useful route experience, and push a bounded change for the Mac executor to integrate. No YouTube/audio changes or broad UI redesign. Base: origin/main b7bee90, isolated branch codex/trip-planner-editable. Mac device fixes are independent and must be preserved.

## Sources
- docs/SPEC.md sections 1, 2, 4: guide the user, existing practice flow, no secrets.
- docs/design/HIG-NOTES.md: native inputs, keyboard/large text, honest states and matching instructions.
- https://developers.google.com/maps/documentation/urls/get-started : universal Directions URL supports origin, destination, travelmode=transit and api=1, requires no API key, opens app or browser. No documented departure-date/time parameter. Checked 25 October 2026.

## Acceptance criteria
1. Tapping a field never inserts an intent-derived station or advances automatically. Native editable origin/destination fields with explicit submission and non-empty validation.
2. Edit both places and select departure date/time, preserving confirmed values and time when going back; reject empty review, keep captions based on typed values.
3. Remove all fabricated trip rows. Provide journey review and explicit Maps handoff carrying typed endpoints and transit mode. Explain that chosen time must be set in Maps; do not represent routes as fetched within NearMe.
4. Keep review visible, allow editing/back and Done; handle unsuccessful URL opening visibly.
5. Update relevant state/voice/target tests; run available checks, clearly separate Windows checks from pending Mac compile/device tests.
6. Commit/push only scoped changes, no secrets/generated Xcode project. No force push or merge; give Mac safe cherry-pick instructions preserving local device fixes.
