# P04c: Ordinary speech stays on device

Status: implemented; Mac validation pending.

## Authorization and scope

The owner chose an on-device default privacy model on 24 October 2026. Ordinary app, widget, guide/practice and Live Activity speech must use the existing Apple system voice. Legacy `naturalVoiceEnabled`, an API key or voice ID must not select cloud speech. Optional family voice is a future cloud concept, not an implemented clone/upload/configuration flow. This decision supersedes the ordinary cloud-TTS default in earlier voice tasks; do not edit SPEC/PLAN/CLAUDE/AGENTS.

Read AGENTS.md, SPEC sections 2-4 for baseline context, speech provider/composition sources, engine prefetch paths, and current screen/recognition/planning sources for the privacy audit. Preserve the widget conversation and existing YouTube handoff. No UI redesign, voice account changes, Maps work or new provider/settings architecture. Retain unused ElevenLabs implementation/tests for future explicitly authorized work. Preserve the preceding widget commit and its pending LOG entry.

## Acceptance criteria

1. One fixed ordinary speech composition supplies the existing SystemVoiceOutputService to the shared app/widget/guide/practice engine and cold Live Activity replies. No ordinary production call site constructs ElevenLabsVoiceOutput.
2. Neither persisted legacy natural-voice preferences nor configured keys/voice IDs can enable cloud speech in ordinary flows. Existing acknowledgement/practice prefetch becomes the system provider's no-op. No family-voice selection is enabled.
3. Add meaningful regressions for production provider selection under legacy preferences and local prefetch behavior. Audit all construction and request sites. Run available static checks; give exact Mac tests without claiming Swift/Xcode execution on Windows.
4. Report a precise dataflow: local recognition/planning/OCR, transient screen frames, filtered temporary local OCR snapshot, no saved screen video; distinguish system asset downloads and third-party app internet use from NearMe sending user content for processing. Keep claims bounded to inspected code and pending device validation.
