## Goal
One tap from the Home Screen or Lock Screen, or "Hey Siri, ask NearMe", opens NearMe straight into listening. Launcher only: no shared data, no App Group, no Live Activity.

## Read
AGENTS.md; docs/design/UI-WIDGETS-REPORT.md Part 2 sections 1, 4, 6 and 7. Files: `project.yml`, `NearMe/NearMeApp.swift` (or the app entry), `NearMe/Info.plist`, `NearMe/Views/Voice/VoiceSessionView.swift`, `SessionContainerView.swift`, `NearMe/ViewModels/TaskPlannerEngine.swift`, `NearMe/Services/Permissions/PermissionsManager.swift`, `scripts/mac-run.sh`, `NearMeTests/`.

Swift 6.4 rule: default arguments must not construct NearMe or test types or read MainActor statics. Minimum iOS 26.5. Do not commit `NearMe.xcodeproj` (generated by XcodeGen). Signing comes from the gitignored `Config/Team.xcconfig`; the new target uses the same team setting.

## Acceptance criteria
### 1. Deep link
- [ ] Info.plist registers URL scheme `nearme`. `nearme://ask` is handled in one place (an `AppEntryRouter` or similar, `.onOpenURL`): it closes any sheet, goes to the voice screen and starts listening using the P04b start path. Other `nearme://` URLs are ignored and logged
- [ ] Works on cold launch and when the app is already running. If onboarding has not been completed, onboarding shows first and listening does not start
- [ ] If a coach or practice session is active, the link does not discard it: it opens the session's dock and starts listening there (same as tapping the dock mic)
- [ ] Microphone or speech permission not determined: the existing permission explanation shows (no auto-listen until granted). Denied: the voice screen shows "Type instead" and "Open Settings", no listening, no repeated prompt
- [ ] On-device speech unavailable for the locale: Type instead, as today. Nothing ever goes to a server

### 2. Widget extension
- [ ] New target `NearMeWidgets` (app extension, WidgetKit) in `project.yml`, embedded in the app, same Swift settings as the app (Swift 5 mode, MainActor default isolation, approachable concurrency), bundle id `<app bundle id>.Widgets`, deployment iOS 26.5. `mac-run.sh quick` still builds and launches
- [ ] Widget kind `AskNearMe`, static configuration, display name "Ask NearMe", description "Open NearMe ready to listen". Families: `.systemSmall`, `.accessoryCircular`, `.accessoryRectangular`
- [ ] systemSmall: `mic.fill` in `.largeTitle`, "Ask NearMe" in `.headline`, accent tint, `.containerBackground(.background, for: .widget)`. accessoryCircular: `mic.fill` on `AccessoryWidgetBackground`. accessoryRectangular: `mic.fill` plus "Ask NearMe". All use `.widgetURL(URL(string: "nearme://ask"))`
- [ ] The widget never says "Listening" (it only launches). VoiceOver label "Ask NearMe, opens NearMe ready to listen"
- [ ] Timeline: a single entry with policy `.never` (nothing changes)

### 3. App Shortcut
- [ ] `TalkToNearMeIntent: AppIntent` in the app target, title "Ask NearMe", `openAppWhenRun = true` (or the iOS 26 `supportedModes` foreground equivalent); `perform()` hands the same `ask` entry to the router used by the deep link
- [ ] `AppShortcutsProvider` with phrases "Ask \(.applicationName)" and "Talk to \(.applicationName)", shortTitle "Ask NearMe", systemImageName "mic.fill"
- [ ] Listening starts only after the app is in the foreground and Siri's audio has finished (reuse the P04b settle delay)

### 4. Tests (default run)
- [ ] Router: `nearme://ask` gives the ask action; unknown host or path is ignored; ask during onboarding does not start listening; ask during an active coach session keeps the session and listens; ask with denied permission gives Type instead
- [ ] The intent's `perform()` calls the same router entry (fake router)

## Verify (Mac and iPhone)
```
bash scripts/mac-run.sh test --current
bash scripts/mac-run.sh quick
bash scripts/mac-run.sh device --current
```
Mac checks on the iPhone: add the small widget to the Home Screen and the circular one to the Lock Screen; tap each with NearMe closed, open in the background, and with the phone locked: NearMe opens listening. Mid-guide, tap the widget: the guide is kept and NearMe listens. "Hey Siri, ask NearMe" opens listening. Deny the microphone in Settings, tap the widget: Type instead and Open Settings show, no prompt loop.
