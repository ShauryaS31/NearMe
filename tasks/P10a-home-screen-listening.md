## Scope and acceptance

1. Add the small interactive widget to the existing NearMeLiveActivity WidgetBundle. Start is an idempotent background AudioRecordingIntent/LiveActivityIntent, never a normal launcher. Explicit setup/recovery links may open NearMe.
2. Foreground setup explains microphone use and obtains existing microphone/speech permissions after onboarding. Background taps recheck permissions, on-device speech availability, and Live Activity authorization without prompting or downloading speech assets.
3. Require a recording Live Activity before capture. Publish Listening only after AVAudioEngine.start succeeds. Show a brief state transition (respect Reduce Motion), a static listening symbol and system elapsed time; no fake audio levels, repeated animation or timeline polling.
4. On-device English recognition endpoints a turn after two seconds of stable words (or Finish), then sends it to the same app-owned NearMe session. The reply is spoken and recognition resumes automatically after a 200ms settle. Keep one hardware capture across recognition pauses; drop buffers while thinking/speaking or other audio plays. Stop/End cancels without submitting a guide-ending command. Repeated starts never toggle off. Stop on interruption, route loss, permission/Live Activity loss or foreground handoff.
5. Silence policy: 45 seconds without words, ONE spoken “Do you still need me?” per session, then 20 seconds grace. Wait/one minute/I'm still here grants 90 seconds. A normal follow-up resets the quiet window. After the check-in has been used, another expired quiet window ends without another nag. Continue preserving the guide while waiting. Bound utterances to 30 seconds; replies to 60 seconds; media pause to 90 seconds; the session to ten minutes followed by at most eight seconds for goodbye. Stop is always available. At most two recognition-error restarts reuse the running engine, then fail visibly.
6. Share only finite status, session token, timing and a needs-in-app-choice boolean with the widget. No user words. Reuse the existing app group. Expiry timelines/stale ActivityKit state and launch reconciliation avoid unbounded saved Listening; widget rendering timing remains system-controlled. Preserve normal in-app voice lifecycle; the explicit widget conversation alone owns the background exception. Setup and spoken status describe English-only recognition and the microphone remaining active through pauses.
7. Author regressions for setup gates, repeat taps, real activation, spoken follow-ups, own-speech/media suppression, check-in/grace/wait/goodbye, guide preservation, interruption, errors, stale actions and lifecycle. Run available static checks; no Swift build/test claim on Windows. Real iPhone cold/warm recording and automatic follow-ups are acceptance gates.

## Primary platform evidence

- [AudioRecordingIntent](https://developer.apple.com/documentation/appintents/audiorecordingintent) requires an active Live Activity throughout recording; the system supplies a recording indicator.
- [Apple WWDC24: Design App Intents for system experiences](https://developer.apple.com/videos/play/wwdc2024/10176/) describes background intents for recording.
- [ActivityKit lifecycle](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities) allows a LiveActivityIntent to start an activity while backgrounded.
- [Widget interactivity](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities) documents app-process LiveActivityIntent execution and reload after perform returns.
- [Widget/Live Activity animations](https://developer.apple.com/documentation/widgetkit/animating-data-updates-in-widgets-and-live-activities) limit data-update animations to two seconds; system timer text is supported.
- [Apple DTS background audio discussion](https://developer.apple.com/forums/thread/816408) concerns a Bluetooth-triggered background request; it does not establish that a user-triggered widget AudioRecordingIntent is universally prohibited. This implementation must still pass the physical-device gate. No private API or communication-framework workaround is permitted.

Read AGENTS.md, P10, P11, SPEC, docs/design/HIG-NOTES.md, project.yml, current audio and lifecycle code. Requested apple-hig/swiftui-design installed SKILL.md files are catalogue stubs; use official guidance above. The owner's explicit orb palette approval applies only to this widget.
